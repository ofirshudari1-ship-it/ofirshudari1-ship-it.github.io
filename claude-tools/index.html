סקילים וסוכנים ל-Claude Code

חמישה סקילים וארבעה סוכנים (subagents) מותאמים אישית, שנבנו תוך כדי ניהול כמה כלי תוכנה במקביל - לא בתכנון מראש, אלא אחרי שאותה בדיקה ידנית חזרה על עצמה שלוש-ארבע פעמים. חינם, בלי חשבון, קוד פתוח.

⬇ הורדת הכל (ZIP) צפייה ב-GitHub

סקילים (Skills)

release-checklist

Skill

מריץ בדיקת שחרור-גרסה לפני כל build: מוודא שמספר הגרסה מסונכרן בכל מקום שהוא צריך להופיע (קובץ הגרסה, שם קובץ ההתקנה, מסך About, יומן שינויים), שההתקנה נבנתה מחדש בפועל ולא נשארה עותק ישן, ושתיקיית הפרויקט נקייה משאריות build. אם לכלי הספציפי יש checklist משלו - עוקב אחריו; אם לא, נופל לכללי סנכרון גלובליים.

מופעל על: "מוכן לשחרור", "בדוק לפני release", "גרסה חדשה", "לפני שאני מוציא installer"

צפייה בקובץ

grep-audit-callers

Skill

לפני שינוי בפונקציה, מודול או API משותף: ממפה קודם את כל הקוראים בעץ הפרויקט המלא (לא רק בקובץ שבו נמצאת ההגדרה), מסווג כל אחד (לא צריך שינוי / צריך עדכון / קוד מת), ומדווח את הרשימה המלאה לפני שנוגעים בקוד. השיטה הזו חשפה 3 באגים אמיתיים ב-3 סבבים נפרדים בפרויקט אמיתי - לא שיטה תיאורטית.

מופעל על: "לשנות פונקציה", "refactor", "מי קורא לפונקציה הזו", "שינוי API משותף"

צפייה בקובץ

secrets-hygiene-check

Skill

בדיקת אפס-secrets לפני commit או release: סורק את קוד המקור (בלי node_modules/dist/build) לתבניות נפוצות של מפתחות API, טוקנים, סיסמאות וחיבורי מסד נתונים, מוודא ש-.gitignore מכסה קבצי סביבה ופרטי גישה, ובודק שהקונפיג באמת נטען ממשתני סביבה ולא קשיח בקוד. כל ממצא חייב ציטוט קובץ+שורה אמיתי; דבר לא ודאי מסומן ⚠️ לבדיקה ידנית ולא נקבע כוודאי.

מופעל על: "בדוק secrets", "לפני commit", "חשש לדליפת מפתח", "בדיקת אבטחה לפני שחרור"

צפייה בקובץ

daily-project-brief

Skill

תקציר מצב קצר על כל הכלים בתיקיית עבודה שיש בה כמה פרויקטים: מה תקוע, מה מיושן, מה דורש תשומת לב - עד 5-7 שורות ממוקדות, בלי audit מלא. מבוסס על מסמך סטטוס מרכזי וקבצי גרסה/יומן שינויים של כל כלי. כשמשהו דורש בדיקה מעמיקה יותר, מפנה לסוכן audit נפרד במקום לבצע אותו בעצמו.

מופעל על: "מה מצב הפרויקטים", "daily brief", "מה תקוע", "סטטוס כל הכלים"

צפייה בקובץ

system-upgrade

Skill

הגדול מבין כולם. תהליך שדרוג מקצה-לקצה לאפליקציית web, Electron או תוסף Chrome קיים: מדרג את המערכת ב-10 ממדים (RTL/עברית, רספונסיביות, נגישות WCAG 2.2, איכות עיצוב, UX ו-states, טפסים, ביצועים נתפסים, קלות הגדרה, שכבת AI, ובריאות קוד ה-UI) באמצעות סקריפט זיהוי דטרמיניסטי ובדיקה חיה בדפדפן - לא רק קריאת קוד. מפיק דוח לפני/אחרי ותוכנית ספרינטים עם יעדים מדידים, מבצע אותה עם commit וצילומי מסך לכל ספרינט, ומעביר את התוצאה למעריך נפרד וסקפטי (ראו agent upgrade-evaluator למטה) במקום לבדוק את עצמו. כולל חומר רקע לכל אחד מ-10 הממדים ותבניות דוח/תוכנית מוכנות.

מופעל על: "תשדרג את המערכת", "המערכת מבולגנת", "תקן RTL/מובייל", "audit UX"

צפייה בתיקייה

סוכנים (Agents)

system-upgrader

Agent

חצי המבצע של תהליך system-upgrade (טוען את הסקיל הזה). סורק מערכת קיימת ומשדרג אותה מקצה לקצה - RTL/עברית, מובייל/דסקטופ, נגישות, עיצוב לא-גנרי, UX/states/טפסים, קלות הגדרה, שכבת AI. מריץ את הבדיקה הדטרמיניסטית ובדיקה חיה בדפדפן, מתעדף ממצאים, ומתקן בספרינטים עם commit וצילומי לפני/אחרי. תמיד רץ יחד עם upgrade-evaluator - אף פעם לא סוכן שמעריך את השדרוג של עצמו.

צפייה בקובץ

upgrade-evaluator

Agent

מעריך נפרד וסקפטי לתוצאות system-upgrader, שרץ ב-context נקי בלי לראות את ההנמקות של הסוכן שביצע את השדרוג (וזו בדיוק הנקודה - מודל שמעריך את העבודה של עצמו נוטה לתת ציון גבוה מדי). קורא את התוכנית והדוח, מריץ את הבדיקה הדטרמיניסטית מחדש, פותח את האפליקציה החיה בדפדפן, בודק כל יעד ספרינט בפועל, ונותן ציון 1-10 לכל אחד מ-10 הממדים עם ראיות. Read-only לגמרי - אף פעם לא נוגע בקוד.

צפייה בקובץ

page-upgrader

Agent

כמו system-upgrader, אבל ממוקד בעמוד או מודול בודד (למשל /calendar, /settings) במקום באפליקציה שלמה. מוסיף שלב מחקר ייעודי - מה עמוד מהסוג הזה אמור לכלול בכלל - לפני שמזהה מה חסר, ואז משדרג עיצוב ו-UX למובייל ולדסקטופ בנפרד, ומוודא ש-tsc/eslint/build עוברים לפני commit. טוען גם הוא את סקיל system-upgrade לכללי הבסיס.

צפייה בקובץ

tool-standards-audit

Agent

מבצע audit מלא לכלי אחד מתוך תיקיית עבודה עם כמה פרויקטים, מול מסמך סטנדרטים מרכזי - בודק את הקוד בפועל עכשיו (לא מעתיק טענות מ-audit קודם בלי לאמת אותן מחדש), כולל ניקיון שורש, סנכרון גרסאות, אפס secrets, RTL/i18n, שפת ומיקום התקנה, single-instance, DPI, והסרה נקייה. כל שורה בדוח חייבת ציטוט קובץ+שורה אמיתי; ❓ עדיף על ניחוש. מעדכן את קובץ ה-audit של הכלי ואת טבלת הסטטוס המשותפת.

צפייה בקובץ

איך מתקינים

מעתיקים את הקובץ (או את כל התיקייה, אצל system-upgrade) לתוך תיקיית ההגדרות של Claude Code:

~/.claude/skills/<שם>/ ← זמין בכל פרויקט
~/.claude/agents/<שם>.md ← זמין בכל פרויקט

או, כדי שיהיה זמין רק בפרויקט ספציפי אחד:

<הפרויקט>/.claude/skills/<שם>/
<הפרויקט>/.claude/agents/<שם>.md

בלי build, בלי התקנת חבילות - קבצי Markdown פשוטים (וסקריפט Python אחד בלי תלויות חיצוניות בתוך system-upgrade).

הערה: שלושה מהסקילים/סוכנים (release-checklist, daily-project-brief, tool-standards-audit) נכתבו במקור מול מבנה תיקיות אישי ספציפי. המנגנון עצמו - בדיקת סנכרון גרסה, מיפוי קוראים לפני עריכה, סירוב להעריך שדרוג של עצמך - כללי ושימושי לכל פרויקט; שמות הנתיבים בשלושת אלה הם דוגמה לעבודה, לא תלות קשיחה.

קוד פתוח, ללא אחריות. שאלות/בעיות: issues בריפו.
